# 过程
- 预处理：处理头文件，比如宏，#include啥的，条件编译，把注释删掉，展开之后得到的是纯c文本，不做语法编辑。输出
后是预处理后的源码文本。
- 编译：把预处理后的c代码翻译成汇编语言（.s），做语法检查，但不生成机器码。
- 汇编：把汇编翻译成机器码，生成目标文件（.o），二进制文本，但是不能直接运行，因为还缺少函数地址。
- 链接：把多个目标文件，系统库合并，解析函数符号地址，生成最终可执行文件，可以在系统中运行了。
# 现象
预处理：处理头文件，比如宏，#include啥的，条件编译，把注释删掉，展开之后得到的是纯c文本，不做语法编辑。输出后是预处理后的源码文本。
编译：把预处理后的c代码翻译成汇编语言（.s），做语法检查，但不生成机器码。
汇编：把汇编翻译成机器码，生成目标文件（.o），二进制文本，但是不能直接运行，因为还缺少函数地址。
链接：把多个目标文件，系统库合并，解析函数符号地址，生成最终可执行文件，可以在系统中运行了。具体来讲，就是把程序里用到的多个 .o 文件和库（如标准库 libc）组合成一个最终可执行文件。链接器负责：
- 解析符号，把 printf 这种函数调用对上真正的地址
- 合并代码段数据段、重定位
- 生成带加载信息、入口点（通常是 main）的最终文件
如果调用了一个不存在或没链接到的函数，就会在链接阶段报“未定义引用”（undefined reference）错误。

gcc -E:将头文件完整展开，输出了非常非常非常非常多的代码，输出的内容包含#行标记。
gcc -S：查看输出的汇编文件，代码相对于上个少了非常多，但是还是比较抽象，看不太懂，但能看出大概结构。
gcc -c:生成.o文件，二进制格式没法查看，cat直接出来一堆乱码。
